# Backtesting Framework

This directory contains a comprehensive backtesting system for comparing different trading strategies, including traditional baseline strategies and deep reinforcement learning (DRL) models.

## Overview

The backtesting framework consists of four main components:

1. **Baseline Strategy Implementation** (`baselines.py`)
2. **Baseline Strategy Backtesting** (`1-run-baselines.py`)
3. **DRL Model Backtesting** (`2-rl-backtest.py`)
4. **Results Visualization** (`3-visualize.py`)

## Files Description

### 1. `baselines.py`

Contains implementations of traditional trading strategies used as baselines for comparison:

- **BuyAndHold**: Benchmark strategy that buys at the start and holds until the end
- **SmaCross**: Trend-following strategy using Simple Moving Average crossover (10/20 periods)
- **RsiReversion**: Mean-reversion strategy using RSI oscillator (30/70 levels)
- **BollingerReversion**: Volatility-based mean-reversion using Bollinger Bands (20-period, 2-std)
- **DonchianBreakout**: Momentum/breakout strategy using Donchian Channels (20-period)

### 2. `1-run-baselines.py`

Automated batch processing script for running all baseline strategies:

**Features:**

- Auto-discovers all strategy classes from `baselines.py`
- Processes multiple CSV files in a folder and subfolders
- Comprehensive logging with timestamped log files
- Multiple output formats (CSV, JSON, pickle, HTML plots)
- Detailed performance statistics and error handling
- Summary reports comparing all strategies

**Usage:**

```python
python 1-run-baselines.py "C:\path\to\your\data"
```

**Output Structure:**

```
result/
├── baseline/
│   ├── [folder_name]/
│   │   ├── [csv_name]/
│   │   │   ├── [strategy]/
│   │   │   │   ├── stats_[timestamp].csv
│   │   │   │   ├── trades_[timestamp].csv
│   │   │   │   ├── equity_[timestamp].csv
│   │   │   │   ├── summary_[timestamp].json
│   │   │   │   └── plot_[timestamp].html
│   │   ├── backtest_summary_[strategy]_[timestamp].csv
│   │   └── strategy_comparison_[timestamp].csv
```

### 3. `2-rl-backtest.py`

Backtesting system specifically designed for trained DRL models:

**Features:**

- Supports both single-file and batch processing modes
- Compatible with Stable-Baselines3 RecurrentPPO models
- Recreates training environment preprocessing
- Handles LSTM state management for recurrent models
- Detailed decision and trade execution logging
- Performance summary statistics

**Usage:**

```bash
# Single file backtesting
python 2-rl-backtest.py --model best_model.zip --params best_params.json --data test_data.csv

# Batch processing (multiple files in a folder)
python 2-rl-backtest.py --model best_model.zip --params best_params.json --data_folder test_data_folder
```

**Key Components:**

- **RLStrategy Class**: Implements backtesting.py Strategy interface
- **Feature Engineering**: Recreates training environment features
- **Action Mapping**: Maps discrete RL actions to trading positions (-1: SHORT, 0: FLAT, 1: LONG)
- **LSTM State Management**: Maintains recurrent model states across timesteps

### 4. `3-visualize.py`

Comprehensive visualization suite for comparing strategy performance.

**Note:** This script only supports CSV files generated by `1-run-baselines.py` and `2-rl-backtest.py`. Input files must be named starting with `backtest_summary_` (for baseline strategies) or `rl_backtest_summary_` (for DRL strategies).

**Features:**

- Performance radar charts for multi-metric comparison
- Risk-return scatter plots with Sharpe ratio color mapping
- Performance heatmaps across different assets
- Statistical significance testing between strategies
- Comprehensive summary tables with rankings
- Individual metric comparison charts

**Usage:**

```bash
# Process CSV files or folders
python 3-visualize.py strategy1.csv strategy2.csv --output-dir plots
python 3-visualize.py /path/to/csv/folder --output-dir plots

# Custom settings
python 3-visualize.py folder --figsize 16 10 --dpi 300 --output-dir high_res_plots
```

**Generated Visualizations:**

- `performance_radar.png` - Multi-dimensional strategy comparison
- `risk_return_scatter.png` - Risk vs. return positioning
- `sharpe_heatmap.png` - Performance across different assets
- `metric_comparison.png` - Individual metric comparisons
- `drawdown_comparison.png` - Risk analysis
- `statistical_significance.png` - Statistical testing results
- `comprehensive_summary.csv` - Detailed performance summary

## Data Requirements

### CSV File Format

All CSV files must contain the following columns:

- `date`: Timestamp (convertible to datetime)
- `open`: Opening price
- `high`: Highest price
- `low`: Lowest price
- `close`: Closing price
- `volume`: Trading volume

### For DRL Backtesting

Additional preprocessed columns required (generated during training):

- Normalized price features (`norm_close`, `norm_high`, etc.)
- Technical indicators (`norm_rsi`, `norm_macd`, etc.)
- Feature columns as specified in training parameters

## Key Performance Metrics

The system calculates comprehensive performance metrics including:

- **Return Metrics**: Total return, annualized return, CAGR
- **Risk Metrics**: Volatility, maximum drawdown, average drawdown
- **Risk-Adjusted**: Sharpe ratio, Sortino ratio, Calmar ratio
- **Trading Efficiency**: Win rate, profit factor, average trade
- **Robustness**: Number of trades, SQN, expectancy

## Configuration

### Backtesting Parameters

- Initial cash: $100,000
- Commission: 0.2% per trade
- No slippage or margin requirements

### Logging

- All operations are logged with timestamps
- Logs saved to `logs/` directory
- Console and file output for real-time monitoring

## Error Handling

The system includes comprehensive error handling:

- File validation before processing
- Strategy-level error isolation
- Graceful degradation with detailed error logging
- Summary reports include success/failure statistics

## Best Practices

1. **Data Quality**: Ensure clean, continuous price data without gaps
2. **Folder Organization**: Use descriptive folder names (e.g., `1d-2015`, `4h-2020`)
3. **Parameter Tracking**: Keep DRL model parameters synchronized with training
4. **Regular Validation**: Compare results across different time periods
5. **Statistical Significance**: Use the built-in statistical tests to validate performance differences

## Output Interpretation

### Strategy Rankings

- Higher Sharpe ratio indicates better risk-adjusted returns
- Lower maximum drawdown indicates better risk management
- Higher win rate with reasonable trade frequency suggests consistency
- Statistical significance tests help validate performance differences

### Visualization Insights

- Radar charts show multi-dimensional strategy strengths/weaknesses
- Risk-return plots help identify efficient strategies
- Heatmaps reveal strategy performance across different market conditions
- Individual metric charts provide detailed performance breakdowns

## Troubleshooting

Common issues and solutions:

1. **Column naming**: Ensure CSV columns match expected format
2. **Date parsing**: Verify date format is recognizable by pandas
3. **Memory usage**: For large datasets, process in batches
4. **Model compatibility**: Ensure DRL model and parameters are compatible
5. **Missing data**: Handle NaN values in technical indicators appropriately
